# Security model

MalVisor's core is strictly static. `analyze` reads file bytes and never executes the target through a subprocess, interpreter, loader, instrumentation, or sandbox. Normal operation has no network requirement, automatic sample download, dynamic analysis, hidden telemetry, or automatic upload.

Input is limited to regular files; symlinks and special files are rejected. The default input cap is 16 MiB and is configurable by CLI. Section count, import descriptors, imported symbols, data directories, field strings, observations, and issues are bounded. Headers, section ranges, and directory counts are checked before extraction. Import descriptors and thunks are iterated with caps. Output is created exclusively, never silently overwritten, and contains no local absolute path. The Phase 2A viewer inserts untrusted strings as React text, never executable HTML.

The browser viewer reads selected JSON with the File API. It does not receive PE bytes, call the Python backend, send reports to a server, use telemetry, or persist reports in localStorage. It uses a build-time validator generated from the repository JSON Schema and additionally rejects reports above 8 MiB, nesting above 48, more than 80,000 object nodes, arrays above 2,500 entries, strings above 4,096 characters, invalid links, unsafe addresses, and out-of-file byte ranges. The raw SVG map uses only positive half-open file ranges within the reported artifact size. Ordinary directory RVAs and VAs are never treated as file offsets. The Content Security Policy keeps scripts local and disallows runtime evaluation; inline CSS is allowed for Vite development styles.

The browser cannot independently authenticate the report's SHA-256 or verify its evidence against original PE bytes, because it reads only the JSON. A malicious but schema-valid report can lie about facts and statuses. Large reports within limits may still use noticeable CPU/memory; browser rendering is not a sandbox. Treat backend `verified` as a provenance statement from the report producer, not a new finding by the frontend.

Static parsing still exposes Python, pefile, and optional native LIEF to hostile bytes. LIEF may parse internal collections before Python can apply every item cap. This is **not a sandbox**; malformed files could trigger library bugs, memory exhaustion, or a process crash. The current parser is suitable for controlled local analysis, not a public upload service. Process isolation and stricter time/memory budgets remain future hardening work. The controls reduce risk but do not promise absolute safety.
